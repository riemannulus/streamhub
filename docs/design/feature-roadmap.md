# 기능 확장 중심 개발 계획

2026-09-09 개정. 시뮬레이터 통합 후에는 사용자가 페이지를 만들고, 작업 문맥에 따라 전환하고, 키로 실제 작업을 수행하는 기능을 우선한다. USB 장애 주입·가상 시계·전송 모델 보정은 별도 선행 단계로 두지 않는다. 새 기능의 필수 검증과 발견된 결함 수정은 각 단계에 포함한다.

## 현재 출발점

- 브라우저 편집기: 페이지 추가·삭제, 고정 키 배치, 앱 Bundle ID 조건, 단일 소스 필터, 페이드, 설정 저장과 JSON 가져오기·내보내기.
- 브라우저 미리보기와 CLI는 렌더러를 공유하지만 실행 조정 경로가 다르다. CLI만 실제 HTTP·SQLite·호스트 표시 경로를 사용한다.
- 자동 선택은 앱 조건만 지원하며 첫 번째 일치 페이지가 선택된다. 수동 페이지는 자동 복귀 버튼을 누르기 전까지 고정된다.
- 고정 키는 텍스트·페이지 이동·자동 모드 복귀만 지원한다. 호스트 표시 경로의 외부 동작 실행은 비활성 상태다.

## 0. 브라우저와 CLI 실행기 통합

**사용자 결과:** 편집기에서 만든 초안을 동일한 실제 호스트 경로로 미리 보고 검증한다.

- `packages/simulator/host.ts`의 실행기를 브라우저와 CLI의 공통 실행기로 만든다. `packages/editor/simulator.ts`는 브라우저 명령·이벤트를 변환하는 역할만 맡긴다.
- 페이지 초안을 바꾸는 기능을 공통 실행기에 추가한다. 초안 적용 중에도 가상 신호와 OS 문맥을 유지하고, 명시적인 저장 전에는 사용자 설정을 변경하지 않는다.
- 브라우저의 샘플 신호 입력도 실제 HTTP 수신 경로를 사용한다. 브라우저 연결별 임시 호스트·DB를 소유하고 종료 시 정리한다.
- 편집기에 현재 초안으로 검증 실행과 결과 열기를 추가한다. 검증기는 고정된 Home/Terminal 이름이나 키 위치를 전제로 삼지 않는다. 구성별로 적용 가능한 검사와 건너뛴 검사를 구분한다.
- 동일한 페이지 정의·입력 시퀀스의 브라우저와 CLI 최종 출력이 같은지 비교한다. 서로 다른 실제 실행 시간으로 생긴 중간 페이드 픽셀까지 동일하다고 요구하지 않는다.

**완료 기준:** 초안 편집 → 신호 입력 → 잠금·해제 → 같은 실행기의 출력 확인 → 기록 열기를 편집기에서 수행한다. 기존 별도 미리보기의 페이지 선택·잠금 처리 중복을 제거한다.

## 1. 페이지를 쉽게 만드는 편집 기능

**사용자 결과:** JSON을 직접 작성하지 않고 업무용 페이지를 빠르게 구성한다.

- 페이지 복제·정렬, 키 복사·붙여넣기, 편집 실행 취소·다시 실행.
- 제목·색상·아이콘을 갖춘 키 스타일. 먼저 내장 아이콘과 제한된 스타일 필드를 지원하고 임의 SVG·외부 이미지 업로드는 뒤로 둔다.
- 페이지 템플릿: 전체 신호, 특정 소스, 작업 도구 모음. 템플릿은 일반 페이지 설정으로 펼쳐져 이후 자유롭게 수정할 수 있다.
- 고정 키와 자동 신호 영역을 구분해 표시한다. 예약 탐색 키와 사용 가능한 신호 자리를 편집 중에 보여 준다.

**주요 변경:** `packages/editor/web/`, `packages/streamdeck/pages.ts`, `packages/streamdeck/render.ts`, 예제 페이지 설정.

**완료 기준:** 템플릿 생성 → 키 편집 → 페이지 복제 → 순서 변경 → 실행 취소 → 저장·재불러오기까지 일관되게 동작한다. 같은 설정이 시뮬레이터와 실제 장치 렌더러에 적용된다.

## 2. 활성 창·화면에 따른 페이지 전환

**사용자 결과:** 같은 앱에서도 현재 창과 작업 위치에 맞는 페이지가 나타난다.

- 조건 편집기를 앱·창 제목·화면 조합으로 확장한다. 첫 버전의 창 제목 조건은 일치·포함으로 제한하고 임의 정규식은 제외한다.
- 화면은 우선 활성 창이 놓인 모니터를 의미한다. macOS Space·전체 화면 데스크톱은 별도 기능으로 분리한다.
- 규칙별 우선순위를 명시한다. 높은 우선순위, 동률이면 설정 순서를 사용하고, 같은 규칙 안의 조건은 모두 충족해야 한다.
- 수동 고정과 자동 복귀 동작을 유지한다. 필요한 문맥이 관측되지 않으면 불일치로 단정하지 않고 현재 페이지를 유지한다.
- 편집기에 현재 모의 문맥, 선택된 규칙, 선택 이유를 표시한다. 시뮬레이터에서 앱·창 제목·모니터를 직접 입력해 실기기 없이 구성한다.
- 실제 창 제목·모니터 수집에 필요한 macOS 권한과 공개 API 지원 범위를 구현 착수 시 확인한다. 프로젝트 조건은 창 제목으로 추정하지 않고 이후 소스가 명시적으로 제공하는 문맥으로 확장한다.

**주요 변경:** `packages/host/src/app-context.ts`, `packages/host/src/display.ts`, `packages/streamdeck/pages.ts`, 공통 시뮬레이터와 편집기 조건 UI.

**완료 기준:** 같은 앱의 두 창과 두 모니터 문맥을 주입해 각 페이지가 선택되고, 우선순위·수동 고정·문맥 미확인 동작을 화면에서 설명할 수 있다. 실제 수집이 지원되지 않는 조건은 지원된 것처럼 표시하지 않는다.

## 3. 키로 실제 작업 실행

**사용자 결과:** 페이지가 작업 상태를 보여 주는 동시에 작업 도구가 된다.

- 1차: URL 열기와 앱 실행·전환을 고정 키 동작으로 추가한다.
- 2차: 사용자가 설정에 등록한 명령을 이름으로 선택해 실행한다. 기존 ActionRegistry의 실행 제한과 허용 인자를 재사용한다.
- 신호 데이터가 임의 명령을 정의하지 않도록 표시 정보와 호스트에 등록한 동작을 분리한다. 코어는 장치와 OS 실행 세부사항을 알지 않는다.
- 시뮬레이터는 실제 외부 동작을 실행하지 않고 실행 의도와 결과 모의를 기록한다. 실제 장치 모드에서만 호스트의 실행 구현으로 전달한다.
- 키에 실행 중·성공·실패 상태를 표시하고, 누르고 있는 동안 중복 실행하지 않는다. 기존 전환·잠금 중 입력 취소 계약을 유지한다.

**주요 변경:** 페이지 버튼 정의, `packages/host/src/actions.ts`, 표시 경로의 intent 처리, 편집기 동작 선택 UI, 시뮬레이터 실행 의도 기록.

**완료 기준:** 같은 키 설정이 미리보기에서는 실행 의도를 보여 주고 실제 모드에서는 등록된 동작을 한 번 실행한다. 실패 상태도 키와 로그에서 확인한다.

## 4. 신호를 업무에 맞게 구성

**사용자 결과:** 각 페이지에서 필요한 신호와 다음 행동을 바로 찾는다.

- 복수 소스·중요도·신선도 필터를 추가한다. 필터 편집 시 현재 조건에 해당하는 신호 수와 페이지 용량을 보여 준다.
- 소스별 영역 배치를 지원한다. 페이지 전체의 자동 배치와 충돌하지 않도록 각 영역이 차지하는 키를 명시한다.
- 화면을 보기 위한 샘플 수 조절에서 확장해, 신호 추가·갱신·삭제와 중요도 변경을 편집기에서 재현한다.
- 실제 사용할 첫 신호 소스 하나를 연결해 페이지·자동 전환·키 동작을 끝까지 사용한다. 대상 소스는 이 단계 착수 시 사용자의 실제 워크플로에 맞춰 선택한다.

**완료 기준:** 선택한 업무의 신호가 도착하고, 해당 페이지에 배치되고, 키로 다음 행동까지 이어지는 한 가지 완성된 사용 흐름을 제공한다.

## 5. 전환 표현 확장

**사용자 결과:** 페이지 성격에 맞는 전환 효과를 선택한다.

- 기존 페이드에 페이지 이동 방향을 반영하는 슬라이드를 추가한다.
- 페이지별 효과·시간 설정과 미리보기 비교를 제공한다.
- 출력은 공통 RGB 렌더링·전송 경로로 처리하고 브라우저 전용 CSS 효과로 대신하지 않는다.
- 상태 확인 주기 100ms를 화면의 프레임 속도로 간주하지 않는다. 효과의 시각적 품질은 실제 전송 속도에 따라 확인한다.

**완료 기준:** 같은 페이지 전환을 효과별로 미리 보고 저장할 수 있으며, 잠금·새 목적지 전환이 발생하면 기존 취소 규칙에 따라 최신 화면으로 끝난다.

## 진행 순서와 범위

통합 → 편집 편의 → 창·화면 문맥 전환 → 키 동작 → 업무 신호 구성 → 전환 효과 순서로 진행한다. 각 단계는 사용할 수 있는 기능과 해당 기능 검증을 함께 완료한다. 이 문서는 후속 기능의 우선순위 계획이며 모든 단계의 일괄 구현 승인을 의미하지 않는다.

USB 장애 주입, 전송 모델 보정, 완전한 가상 시간, 장시간 스트레스 검사는 독립적인 다음 단계에서 제외한다. 다만 기능 개발 중 실제 결함이 드러나면 그 기능의 완료 범위 안에서 수정한다.
