# 실제 호스트를 사용하는 자동 시뮬레이터

`bun run simulator:check`는 데스크톱 잠금과 무관하게 실행된다. 실행 중인 Streamhub, 사용자의 설정·DB, 실제 Stream Deck에는 접근하지 않는다. 컴퓨터 자체가 잠자기에 들어가면 프로세스도 진행하지 못하므로 화면 잠금과 시스템 잠자기는 구분한다.

## 공유하는 실행 경로

CLI → 실제 인증 HTTP → 실제 SignalStore/SQLite → startDisplay → PageBoard/DisplayLifecycle → HidDisplay/renderKey → 가상 장치의 키별 RGB 기록.

`startHost`와 `startDisplay`의 기존 의존성 주입을 사용한다. 장치 연결, 세션 감시, 앱 감시만 가상 구현으로 대체한다. 표시 갱신 주기는 실제 호스트의 기본값인 100ms이고, 페이지 선택의 debounce와 페이드 시간도 실제 코드가 처리한다. 가상 시계는 아직 사용하지 않는다. 각 실행은 임시 디렉터리와 임시 loopback 포트를 소유하며 재시작 시 같은 DB를 다시 열고 종료 시 제거한다. 임시 인증 토큰은 결과 파일에 기록하지 않는다.

브라우저 편집기는 기존의 가벼운 메모리 미리보기를 유지한다. 이 CLI가 저장·재시작까지 포함한 통합 검증 경로이며, 브라우저 미리보기와 실행 조정 로직까지 완전히 통합한 상태는 아니다.

## 자동 판정

- `persistence`: HTTP 수신·표시, 수동 페이지 고정, DB 재시작 복원, HTTP 삭제.
- `locked-update`: 잠금 후 픽셀 쓰기 금지, 잠금 중 신호 저장, 해제 후 최신 내용 출력.
- `held-key`: 누른 상태에서 잠금·해제해도 이전 키 해제로 이동하지 않으며, 새 누름은 정상 동작.
- `app-routing`: 활성 앱에 따른 자동 선택, 수동 고정, 자동 모드 복귀, 조회 실패 시 페이지 유지.
- `interrupted-transition`: 키별 전송 지연을 넣고 페이드 도중 잠금, 이어지는 목적지 변경 후 최신 화면 수렴.

각 시나리오는 종료 시 대기 명령과 핸들 해제도 확인한다. 기대하는 페이지·신호 내용과 입력 허용 상태를 확인한 뒤 15개 키의 실제 전송 RGB를 최종 렌더링 결과와 비교한다. 같은 렌더러를 쓰는 비교는 전송 누락·중간 프레임 잔류를 검증하며, 렌더러 자체의 글꼴이나 디자인이 올바른지는 PNG를 별도로 확인해야 한다. 대기 상태의 회색 이미지는 명령 수신을 시각화하며 실제 펌웨어 로고를 재현하지 않는다.

## 결과 파일

출력 기본 위치는 `.streamhub/simulator/<timestamp>/run-<unique>/`다. `--out`을 지정해도 그 안에 새 실행 디렉터리를 만들므로 기존 증거를 덮어쓰지 않는다.

- `summary.json`: 전체 성공 여부와 시나리오 결과. 실패·취소 시 CLI는 0이 아닌 종료 코드를 반환한다.
- `<scenario>/summary.json`: 개별 판정과 오류.
- `<scenario>/trace.jsonl`: 시간순 입력·잠금·문맥·연결·프레임·키 전송 기록. `key.asset`은 `rgb/<sha256>.rgb`를 참조하며 raw RGB 크기는 72×72×3이다.
- `<scenario>/replay.html`: 네트워크 없이 열 수 있는 타임라인. 개별 키 전송 순서와 부분 갱신을 그대로 재생한다.
- `<scenario>/*.png`: 주요 단계, 최종 활성 화면, 실패 시점의 5×3 키 출력.

RGB 자산은 내용 해시로 중복 제거한다. 기록기는 최대 50,000개 이벤트·4,096개 고유 키 이미지를 허용하며 한도 초과는 성공으로 처리하지 않는다. 현재 CLI는 유한한 내장 시나리오용이며 장시간 운영 이벤트 수집기는 아니다.

## 검증과 남은 범위

5개 CLI 시나리오, 전체 테스트 135개, 타입 검사, 빌드, HTTP·DB 데모를 통과했다. 실패 시나리오의 보고서와 서버 정리, 녹화 오류가 성공 보고서를 남기지 않는 경우도 테스트한다.

실기기 전송 시간으로 지연 모델을 보정하고 USB 오류·재연결과 OS 이벤트 누락을 주입할 수 있다. 완전한 가상 시간 제어, 사용자 시나리오 JSON, 실제 OS 이벤트 녹화, 브라우저와 호스트 시뮬레이션 실행기의 통합은 이번 범위에 포함하지 않는다. 실제 패널 밝기·잔상·USB 펌웨어 동작은 실기기 검증이 필요하다.
