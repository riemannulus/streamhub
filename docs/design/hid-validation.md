# Stream Deck MK.2 실기기 검증

2026-09-08, Bun 1.4.0, `@elgato-stream-deck/node` 7.6.3.

- 장치: Stream Deck MK.2 (`original-mk2`), 펌웨어 1.02.000.
- 키: 15개, 각 72×72 RGB 입력 이미지.
- HID 열기, 펌웨어 읽기, 15개 키 이미지 전송, 전송 후 펌웨어 재조회 성공.
- 출력: 01–15 흰색 번호, 행별 빨강/초록/파랑 상단 띠, 좌상단 노란 방향 표시.
- 사용자 육안 확인: 정상적으로 보임.
- 입력 확인: 01번 및 15번 키 각각 down/up 수신.
- 관측된 HID 오류: 0건.
- 전체 이미지 생성 및 순차 전송: 431.58ms. 첫 키 쓰기 415.72ms, 나머지 키 쓰기 약 0.93–1.35ms. 단일 실행의 측정이며 지속 FPS 보장은 아님.
- 종료: 45초 입력 관측 뒤 프로세스 정상 종료, HID 연결 닫힘. 진단 패턴은 장치에 유지.

재실행: `bun run hid:check --listen=45`. 로컬 원시 결과는 `.streamhub/hid-check.json`에 저장한다.

이 초기 진단 시점에는 타입 검사 및 전체 테스트 52개 / 234 assertions가 통과했고, 데몬 출력과 실제 focus action은 아직 연결하지 않았다.

후속 복구: 사용자 요청으로 `bun run hid:restore`를 실행해 Show Logo 명령 전송 성공. 진단 기본 종료 동작도 기본 대기화면 복귀로 변경했다. 과거 기록의 패턴 유지는 최초 검증 당시 동작이다.

## 자동 대기화면 구현 후 검증

호스트의 SessionDeck 상태를 실제 HID에 연결하고, macOS 세션 상태에 따라 대기화면·재연결·최신 전체 프레임 복원을 수행하도록 구현했다. 물리 입력은 탐색·핀만 처리하며 외부 focus action은 실행하지 않는다.

- `bun run hid:lifecycle-check`: 실제 장치에서 대기화면 → ACTIVE → 대기화면 → RESTORED → 종료 대기화면 시퀀스 성공, HID 오류 0건.
- 첫 60초 잠금 관찰은 사용자 잠금 전에 종료되어 검증 불충분으로 처리했다.
- 5분 관찰에서 실제 잠금 알림과 Show Logo 전송·HID 닫기를 확인했으나 해제 후 복원 실패. 사용자가 실패를 확인했다. 같은 시점 새 helper의 `--once`는 active, 기존 helper는 locked를 유지해 네이티브 잠금 판정에 원인을 좁혔다.
- 잠금 해제 시점의 일시적인 이전 상태 또는 해제 알림 누락 뒤, 잠금 키가 없어져도 이전 잠금 판정이 영구 유지되는 경로를 수정했다. 해제 요청을 보존하며, 알림 누락 시에도 유효한 활성 콘솔에서 잠금 키가 2초 연속 없으면 복구한다.
- 수정 후 실제 잠금 → Show Logo·HID 닫기 → 해제 → HID 재연결·전체 프레임 전송을 로그에서 확인했다. 사용자도 **대기화면 → ACTIVE 정상 복귀**를 확인했다. 진단 SIGINT 종료 시 Show Logo 전송과 HID 닫기 성공, 오류 0건.
- 최종 `bun run check`: 타입 검사와 79개 테스트 / 338 assertions 통과. 실제 Swift 소스를 컴파일한 잠금 상태 회귀 검증 11개 조건을 포함한다. `bun run build`, `bun run demo`도 통과했다.

잠긴 상태에서 새 helper를 시작하는 경우는 네이티브 상태 테스트로 검증했으며, 이번 실기기 관찰에서는 실행 중 잠금·해제 전환을 검증했다. 로컬 원시 결과는 `.streamhub/hid-lifecycle-check.json`에 저장하며 커밋하지 않는다.

시스템 전체 잠자기의 USB 전원 중단 시점, SIGKILL 및 케이블 분리 뒤 명령 전송은 보장하지 않는다.
