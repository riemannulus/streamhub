# 로컬 신호 버스 → 스트림덱 설계 (v3)

두 문장이 이 문서를 지탱합니다.

- **코어는 무엇이 꽂혔는지 모릅니다.**
- **버스는 슬롯까지, 페이지는 뷰의 일입니다.**

## 비유: 콘센트

220V 콘센트는 냉장고가 꽂힐지 선풍기가 꽂힐지 모릅니다. 규격만 정해두고 기기를 모르는 덕분에, 새 가전이 나올 때마다 벽을 뜯지 않아도 됩니다.

claude-deck 은 콘센트가 아니라 납땜입니다. 훅에서 온 데이터가 슬롯 배정과 렌더링까지 한 덩어리로 이어져 있어서, Sentry 를 붙이려면 그 배선 안으로 들어가야 합니다. 소스가 하나일 때는 이게 가장 짧은 코드지만, 두 번째를 붙이는 순간 비용이 튑니다.

그래서 이 설계의 목표는 기능을 늘리는 게 아니라 **꽂는 구멍의 규격을 정하는 것**입니다.

## 문제와 대응

이 구조는 유행을 따라간 결과가 아니고, 논의에서 나온 문제를 하나씩 대응한 결과입니다.

| 문제 | 새 구조에서 대응하는 것 |
|---|---|
| 소스마다 슬롯 배정을 각자 알아야 함 | 소스는 `emit` 만 받습니다. 슬롯 개념에 접근할 수 없습니다 |
| cmux/Orca 가 코어에서 특별 대우를 받음 | 코어가 contrib 를 import 하지 않습니다. 린트로 막습니다 |
| 소스를 추가하려면 TS 를 써야 함 | 등록 경로가 셋입니다. 대부분 선언 파일에서 끝납니다 |
| 임의 명령 실행 경로 | 액션은 사전 등록된 이름만 부릅니다 |
| 지속되지만 개수가 가변인 것을 표현 못 함 | `kind: "live"` 를 추가했습니다 |
| 비정상 종료 후 죽은 키가 남음 | 스냅샷 모드로 주기 교정합니다 |
| 15키를 종류별로 쪼개면 다 좁아짐 | 페이지 단위로 나눕니다. 한 종류가 12키를 씁니다 |
| 페이지를 나누면 다른 페이지가 안 보임 | 좌우 버튼이 옆 페이지의 요약 게이지입니다 |
| 스트림덱 전용 구조 | 트랜스포트도 플러그인입니다. 페이징은 뷰 층에 있습니다 |

## 규격: 신호 세 종류

v2 의 이분법으로는 세션을 표현할 수 없었습니다. 세션은 지속되면서 개수가 가변인 세 번째 칸입니다.

| | 지속되나 | 개수 | 누르면 | 사라지는 시점 |
|---|---|---|---|---|
| `event` | 아니오 | 가변 | 사라집니다 | ack 또는 TTL |
| `gauge` | 예 | 고정 | 사라지지 않습니다 | 사라지지 않고 갱신만 |
| `live` | 예 | 가변 | 사라지지 않습니다 | 소스의 철회 |

`live` 가 `event` 와 다른 점은 둘입니다. ack 로 지워지지 않고, 슬롯 경쟁을 같은 `live` 끼리만 합니다. 아직 돌고 있는 세션이 Sentry 알림에 밀려 화면에서 사라지면 안 되니까요.

```ts
type Level = "info" | "warn" | "urgent";

type Press =
  | { type: "ack" }
  | { type: "open"; url: `https://${string}` }
  | { type: "action"; name: string; args: Record<string, string> };

type Signal = {
  kind: "event" | "gauge" | "live";
  id: string;        // 중복 제거 키. 같은 id 재발행은 새 슬롯이 아니라 갱신입니다
  source: string;
  level: Level;
  label: string;
  value?: string;    // gauge 용. "3", "94%"
  press: Press;
  ttlMs?: number;    // event 용. 없으면 ack 까지 유지합니다
};
```

이게 플러그의 모양 전부입니다. 이 JSON 을 만들 수 있으면 소스가 될 수 있습니다.

## 등록 경로 셋

난이도 순으로 셋입니다. **아래로 갈수록 강력하고, 위로 갈수록 짧습니다.**

### 1. 선언 — 코드 0줄

주기적으로 뭔가를 실행하거나 HTTP 를 찔러서 JSON 을 얻고, 일부를 신호로 매핑하는 경우입니다. 폴링 소스는 거의 전부 여기서 끝납니다.

```toml
[[source]]
name = "gha-queue"
kind = "gauge"
poll = "60s"
exec = ["gh", "api", "repos/cookieplace/crepe/actions/runs?status=queued"]

[source.map]              # 값은 jq 식입니다
id      = '"gha:queue"'
label   = '"queue"'
value   = '.total_count | tostring'
level   = 'if .total_count > 5 then "warn" else "info" end'
```

`level` 을 jq 식으로 쓸 수 있게 한 게 의외로 큽니다. "언제 노랗게 변하나"가 코드가 아니라 설정 한 줄이 됩니다.

### 2. 스크립트 — 언어 무관

매핑이 jq 로 표현되지 않거나 상태를 조금 들고 있어야 할 때입니다. 실행 파일이 stdout 에 JSON Lines 로 신호를 뱉으면 됩니다.

```toml
[[source]]
name = "doorbell"
kind = "stream"
exec = ["~/bin/doorbell-watch"]   # 한 줄에 신호 하나
```

fish 스크립트여도 되고 파이썬이어도 됩니다. 호스트는 프로세스를 살려두고 죽으면 백오프로 재시작하는 일만 합니다.

### 3. 모듈 — TS

장기 연결이나 복잡한 상태 기계가 필요할 때만 씁니다. 자주 여기까지 내려간다면 1번의 표현력이 부족하다는 신호입니다.

### 그리고 push

위 셋과 별도로, 아무 데서나 던질 수 있는 문을 둡니다.

```
POST   /signal        본문은 Signal 그대로
DELETE /signal/{id}   철회
```

Claude Code 훅용 전용 엔드포인트를 만들지 않는 게 요점입니다. 훅도, cron 도, `curl` 한 줄도 전부 같은 문으로 들어옵니다. 새 알림을 붙일 때 제일 먼저 시도할 수 있는 게 이거여야 합니다.

`DELETE` 가 `live` 를 가능하게 하는 조각입니다. 세션은 ack 로도 TTL 로도 사라질 수 없으니, 소스가 "이제 없다"고 말할 통로가 필요합니다.

**소스가 특별해지는 지점이 한 곳도 없습니다.**

## 스냅샷 모드 — 좀비 슬롯 방지

`live` 를 push 로만 관리하면 반드시 깨집니다. `SessionEnd` 훅은 정상 종료 경로에서만 돌고, SIGKILL·OOM·크래시·전원 차단에서는 아예 발화하지 않습니다. 죽은 세션의 키가 영원히 남아 존재하지 않는 패널로 점프하게 됩니다.

드문 일이 아닙니다. cmux 생태계에 크래시·전원 차단·OOM 이후 세션을 복구하는 도구가 따로 나와 있을 정도입니다.

**push 로 즉시 반영하고, 폴링으로 교정합니다.**

```toml
[[source]]
name = "live-sessions"
kind = "live"
mode = "snapshot"        # 매번 전체 목록. 사라진 id 는 코어가 자동 철회합니다
poll = "20s"
exec = ["~/bin/list-live-sessions"]
```

스크립트는 지금 살아있는 세션 목록만 뱉습니다. `ps` 로 claude 프로세스를 찾아 `--session-id` 를 긁는 방식이 확실하고, cmux 세션이라면 cmux CLI 조회로도 됩니다.

스냅샷 모드가 세션 전용이 아닌 게 이 방식의 장점입니다. 열린 PR 목록, 미해결 Sentry 이슈, 실행 중인 컨테이너 — "현재 존재하는 것들의 집합"은 전부 같은 패턴입니다.

## 라우팅: 페이지로 보냅니다

v2 는 15키를 종류별 존으로 쪼갰습니다. 페이지가 있으면 그럴 필요가 없습니다. 한 종류가 12키를 다 씁니다.

```toml
[[route]]
match = { kind = "live" }
page = "claude"

[[route]]
match = { source = "sentry" }
page = "alerts"

[[route]]
match = { level = "urgent" }
pin = true              # 어느 페이지에 있어도 핀 키에 보입니다

[[route]]
match = {}
page = "alerts"
priority = 10
```

위에서부터 첫 매치를 씁니다.

## 슬롯 배정

페이지 안에서만 경쟁합니다.

1. 같은 `id` 로 오면 새 슬롯을 잡지 않고 기존 슬롯을 갱신하며 카운터를 올립니다.
2. 빈 슬롯이 있으면 **가장 낮은 인덱스**에 배정합니다.
3. 꽉 찼고 새 신호의 `priority` 가 더 높으면, 가장 낮은 것 중 가장 오래된 것을 밀어냅니다.
4. `live` 는 밀려나지 않습니다. 대신 페이지가 넘칩니다(아래 스필오버).

**사라진 슬롯을 메우려고 재정렬하지 않습니다.** 3번 키가 그 세션이라는 근육 기억이 생긴 뒤에 배열이 밀리면 반드시 잘못 누릅니다. 구멍은 구멍으로 남기고 새 신호가 가장 낮은 빈 인덱스로 들어갑니다.

### 스필오버

Orca 로 다섯 개에 cmux 로 몇 개 더 열면 12키를 넘깁니다. 선언에는 `page = "claude"` 라고만 쓰고, 넘치면 코어가 `claude:2` 를 만들어 좌우 순환에 끼워 넣습니다.

오버플로 키에 `+3` 만 띄우는 v2 방식보다 이쪽이 낫습니다. `live` 는 실제로 눌러야 하는 대상이고, 세어보라고 있는 게 아닙니다. `event` 는 여전히 오버플로 카운터로 처리합니다 — 유실은 하되 유실했다는 사실은 보입니다.

## 페이징은 뷰의 일입니다

버스가 페이지를 알면 안 됩니다. 감시 액자는 페이지가 없고 전부 한 화면에 뿌리니까요. 버스는 슬롯 배정까지만 하고, 페이징은 트랜스포트별 뷰 설정으로 둡니다.

```toml
[transport.streamdeck]
pages = ["claude", "alerts", "ci"]
prev = 10
next = 14
pin = 13
returnToFirstAfter = "30s"

[transport.frame]
# 페이지 없음. 전부 표시합니다
```

마지막 줄이 이 배치의 이유입니다. `Transport` 인터페이스에 페이지 개념을 넣었다면 액자 쪽에 쓸모없는 설정이 생겼을 겁니다.

### 좌우 버튼은 네비게이션이 아닙니다

물리 장치를 쓰는 이유가 "고개만 돌리면 보인다"인데, 페이징을 하면 다른 페이지가 안 보입니다. 그대로 두면 스트림덱의 존재 이유가 반쯤 사라집니다.

**좌우 버튼은 옆 페이지의 요약 게이지여야 합니다.** 그 방향에 미확인 신호가 몇 개인지, 최고 심각도가 무엇인지를 버튼에 그립니다. 오른쪽 버튼이 빨갛게 `2` 를 띄우면 "오른쪽에 urgent 두 개"라는 뜻입니다. 넘겨보지 않아도 넘길 이유가 있는지는 항상 보입니다.

페이지 번호는 별도 키를 쓰지 말고 오른쪽 버튼에 겹쳐 그리십시오. 12키를 지키는 게 낫습니다.

### 자동 전환은 넣지 않습니다

urgent 가 들어오면 그 페이지로 자동 전환하는 게 당연해 보이지만, 이건 위치 안정성을 정면으로 깨뜨립니다. 손이 이미 3번 키로 가고 있을 때 배열이 바뀌면 오폭합니다. 세션 승인 버튼이 있던 자리에 다른 게 와 있는 상황이요.

대신 핀 키를 씁니다. 어느 페이지에서도 같은 자리에 보이는 슬롯 하나에 urgent 를 띄웁니다. 배열은 그대로고 정보는 도달합니다.

### 키 예산 (15키)

| | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 상단 | 내용 | 내용 | 내용 | 내용 | 내용 |
| 중단 | 내용 | 내용 | 내용 | 내용 | 내용 |
| 하단 | ← 요약 | 내용 | 내용 | 핀 | → 요약 |

내용에 12키가 남습니다. XL(32키)이라면 이 고민 자체가 사라집니다.

`returnToFirstAfter` 는 취향인데 저는 넣는 쪽을 권합니다. 알림 페이지를 보다 그대로 두면 Claude 페이지가 안 보이는 상태로 방치되는데, 기본 페이지는 항상 기본값으로 돌아와 있는 게 신뢰하기 쉽습니다.

## 액션도 등록입니다

버튼을 눌렀을 때 할 일도 같은 방식으로 등록합니다. cmux 든 Orca 든 코어에 이름이 박히지 않습니다.

```toml
[[action]]
name = "cmux:focus"
exec = ["/opt/homebrew/bin/cmux", "focus", "--session", "{sessionId}"]
args = { sessionId = "^[A-Za-z0-9-]{1,64}$" }

[[action]]
name = "orca:decide"
exec = ["/opt/homebrew/bin/orca", "gate", "{gateId}", "--{verdict}"]
args = { gateId = "^[a-z0-9-]{1,64}$", verdict = "^(approve|reject)$" }
```

`{}` 치환은 셸을 거치지 않고 argv 배열에 그대로 들어갑니다. `args` 의 정규식은 zod 로 컴파일되어 호출 전에 검증합니다. 외부에서 들어온 문자열이 명령으로 승격될 경로가 없습니다.

v1 의 `{ type: "exec"; command: string }` 은 폐기했습니다. 그건 Sentry 이슈 제목 하나로 내 맥북에서 명령이 도는 구멍이었습니다.

## 트랜스포트

```ts
type Transport = {
  name: string;
  capabilities: { keys: number; keySize: number; maxFps: number };
  write(states: KeyState[]): Promise<void>;
  onPress?(handler: (index: number) => void): void;
};
```

`maxFps` 를 능력치로 노출하는 게 요점입니다. 직접 HID 는 30 을, SDK 플러그인은 10 을 보고합니다. 렌더러는 그 숫자만 보고 맞추므로 갈아탈 때 렌더러를 고칠 일이 없습니다. `onPress` 가 옵셔널인 이유는 액자처럼 출력만 하는 싱크가 있기 때문입니다.

렌더링은 두 단계입니다. 배경 애니메이션 프레임은 부팅 시 한 번 인코딩해 캐시하고, `label` 이 확정되는 순간 그 슬롯의 전체 시퀀스를 한 번 합성해 캐시합니다. 매 프레임 텍스트를 합성하면 CPU 가 갈립니다. 렌더러 앞에는 coalesce 큐를 두어, 버스가 한 tick 에 신호를 다섯 개 처리해도 쓰기는 한 번입니다.

페이지 전환도 여기서 처리합니다. 보이지 않는 페이지의 슬롯은 프레임을 만들지 않습니다.

## 패키지 경계

```
packages/
  core/                    # Signal, 라우팅, 슬롯, 철회, 스냅샷 diff
  host/                    # 데몬. 레지스트리 로딩, HTTP, 프로세스 관리
  transport-streamdeck/    # 페이징·핀·요약 게이지가 여기 삽니다
  transport-frame/
contrib/                   # 선언 파일. cmux.toml, orca.toml, sentry.toml, kb.toml
```

`core` 는 `contrib` 도 `transport-*` 도 import 하지 않습니다. 의존성은 안쪽으로만 흐릅니다. contrib 를 통째로 지워도 코어가 빌드됩니다 — 이게 "이것만을 위한 게 아니다"의 검증 방법입니다.

## contrib 예시: Claude Code 세션

훅 이벤트는 세 가지 주기로 갈립니다. 세션당 한 번(`SessionStart`, `SessionEnd`), 턴당 한 번(`UserPromptSubmit`, `Stop`, `StopFailure`), 매 도구 호출(`PreToolUse`, `PostToolUse`).

`Stop` 은 턴 단위입니다. 세션 종료가 아니라 응답 하나가 끝난 것이니, `Stop` 을 완료로 쓰면 안 됩니다. claude-deck 이 이 착각을 하고 있습니다.

| 훅 | 하는 일 |
|---|---|
| `SessionStart` | `POST /signal` — `kind: "live"`, level `info` |
| `PermissionRequest` | 같은 `id` 로 재발행, level `urgent` |
| `Stop` | 같은 `id` 로 재발행, level `info` |
| `SessionEnd` | `DELETE /signal/{id}` |

같은 `id` 로 재발행하는 게 슬롯을 유지한 채 색만 바꾸는 방법입니다. `id` 는 `session_id` 를 씁니다.

`PermissionRequest` 훅은 권한 다이얼로그가 뜰 때 발화하므로 대기 상태를 `Notification` 보다 정확히 집습니다. 다만 `SessionEnd` 훅의 타임아웃은 짧습니다 — 과거에는 설정값과 무관하게 1.5초 후 강제 종료됐고 v2.1.74 부터 설정을 따릅니다. 로컬 `DELETE` 한 번이면 충분하지만 여기에 무거운 작업을 넣으면 잘립니다.

`SessionStart` 는 재개 시에도 발화하고 `source` 가 `resume` 이나 `fork` 로 들어옵니다. cmux 나 Orca 가 크래시 후 세션을 복원하면 키가 저절로 다시 나타납니다.

훅은 cmux 것과 별도로 겁니다. cmux 명령을 감싸는 래퍼를 만들면 내 스크립트가 깨질 때 cmux 알림까지 같이 죽습니다.

### cmux 를 진실의 원천으로 둡니다

cmux 는 이미 `cmux claude-hook` 으로 훅을 받고 session_id 를 workspace·surface·cwd 에 연결해 저장합니다. 데몬이 창 매핑을 따로 만들면 두 매핑이 어긋나 엉뚱한 패널로 점프합니다.

그래서 `cmux:focus` 액션이 `sessionId` 만 받습니다. 창 좌표를 데몬이 모르니 어긋날 수가 없습니다.

Orca 는 격리된 worktree 로 돌아가므로 `cwd` 마지막 세그먼트가 프로젝트명이 아니라 worktree 이름입니다. 같은 리포에 worktree 다섯 개면 전부 같은 이름으로 보이니 `label` 은 브랜치명이나 태스크명에서 뽑습니다.

## 이 규격으로 같이 꽂히는 것들

범용성의 증거는 목록입니다. 아래 전부 코어를 건드리지 않습니다.

| 꽂을 것 | 등록 경로 | 종류 |
|---|---|---|
| 실행 중인 dev 서버 | 선언(스냅샷) | live |
| 열린 내 PR | 선언(스냅샷) | live |
| 배포 승인 대기 | push | event |
| 현관 초인종 | 스크립트 | event |
| 다음 회의까지 남은 시간 | 선언(폴링) | gauge |
| 미flush KB 원장 | 선언(파일 워처) | gauge |
| 세탁기 종료 | push | event |

## 무엇이 규칙을 막는가

| 어긴 규칙 | 무엇이 막는가 |
|---|---|
| `core` 가 `contrib` 나 `transport-*` 를 import | 린트. 의존성 방향 규칙 |
| 소스가 슬롯이나 페이지를 직접 지정 | 타입. `Adapter` 는 `emit` 외에 아무것도 받지 않습니다 |
| `core` 가 페이지를 앎 | 타입. `Transport` 인터페이스에 페이지가 없습니다 |
| 등록되지 않은 명령 실행 | 타입. `Press` 에 명령 문자열을 담을 자리가 없습니다 |
| 액션 인자에 이상한 값 | `args` 정규식 검증. 호출 전에 거부됩니다 |
| 치환값이 셸 메타문자로 동작 | argv 배열 전달. 셸을 거치지 않습니다 |
| `live` 가 알림에 밀려 사라짐 | 페이지 분리. 경쟁은 같은 페이지 안에서만 |
| 죽은 세션 키가 남음 | 스냅샷 diff. 20초 안에 교정됩니다 |
| `maxFps` 초과 전송 | 렌더러의 coalesce 큐 |
| 훅이 데몬 부재 시 Claude Code 를 블록 | 훅 CLI 의 타임아웃과 무조건 exit 0 |
| 어떤 알림이 진짜 urgent 인지 | 사람의 판단 |

마지막 줄이 남는 게 정상입니다. urgent 를 남발하면 핀 키가 늘 빨개져서 아무 의미가 없어지는데, 이건 어떤 타입으로도 막을 수 없습니다. 대신 막을 수 없다는 걸 알고 있으면 소스를 추가할 때 그것만 보게 됩니다.

## 예상 반박

> "규격을 좁게 정하면 특수한 소스는 못 꽂는 거 아닌가요?"

그래서 등록 경로를 셋으로 뒀습니다. 규격이 좁은 건 신호의 모양(`Signal`)이고, 그 모양을 만드는 방법은 제한하지 않았습니다.

> "페이지를 나누면 결국 못 보는 정보가 생기는데요."

맞습니다. 그래서 좌우 버튼을 네비게이션이 아니라 요약 게이지로 만들고 핀 키를 뒀습니다. 그래도 완전히 회복되지는 않습니다 — 아래 트레이드오프에 적었습니다.

> "선언 파일에 jq 식을 쓰는 건 결국 코드 아닌가요?"

맞습니다. 다만 빌드와 재시작이 필요 없는 코드입니다. "노랗게 변하는 기준"을 바꾸는 데 컴파일이 필요하면 실제로 아무도 안 바꿉니다.

## 트레이드오프

- **페이징은 즉시성을 일부 포기하는 선택입니다.** 요약 게이지와 핀 키로 대부분 회복되지만, "옆 페이지 3번째 세션이 방금 노랗게 변했다"는 정보는 넘겨보기 전까지 알 수 없습니다. 저는 종류마다 6키로 좁아지는 것보다 이 손실이 낫다고 봅니다.
- **범용 프레임워크를 먼저 만들면 아무것도 안 쓰게 될 위험이 있습니다.** 이게 이 문서의 가장 큰 비용입니다. 그래서 구현 순서에서 선언 로더와 페이징을 1단계에 넣지 않았습니다.
- **선언의 표현력에는 천장이 있습니다.** jq 로 안 되는 게 나오면 스크립트로 내려가야 하고, 그 경계가 어디인지는 몇 개 붙여보고서야 압니다. 처음부터 문법을 넓히려 들지 않는 게 낫습니다.
- **스냅샷 폴링은 최악 20초 늦습니다.** 죽은 키가 20초 남습니다. 더 줄이면 `ps` 를 자주 돌게 되니 저는 20초가 적당하다고 봅니다.
- **데몬이 단일 장애점입니다.** 컴퓨터가 꺼지면 전부 멈춥니다. 게이지 소스를 상시 켜져 있는 액자 쪽 미니PC 로 옮겨 이중화할 수 있지만, 초기에는 데스크톱 단일 데몬으로 두고 액자를 트랜스포트로만 붙이는 게 낫다고 봅니다.
- **Orca 는 급변 중입니다.** 3월 첫 커밋 이후 반년도 안 됐고 CLI 가 깨질 가능성이 높습니다. 그래서 선언 파일로 두는 게 유리합니다 — 깨지면 그 파일만 고치고, 시작 시 CLI 버전이 모르는 값이면 그 소스만 비활성화하고 나머지는 살립니다.
- **스트림덱이 cmux 와 겹칩니다.** cmux 는 이미 알림 링과 배지와 데스크톱 알림을 줍니다. 스트림덱이 채우는 빈틈은 둘뿐입니다. cmux 와 Orca 를 합쳐 보는 유일한 화면이라는 것, 그리고 앱 창 밖에 있을 때도 사라지지 않는다는 것. 그 외의 정보를 올리려는 충동은 참는 게 좋습니다.

## 구현 순서

- **high** — `Signal` 세 종류, `POST`/`DELETE` push, 스트림덱 트랜스포트(직접 HID), 렌더러. 페이지는 `claude` 하나뿐이므로 좌우 버튼도 페이징 코드도 없습니다. 소스는 훅 push 와 `ps` 스냅샷 스크립트 둘. 좀비 슬롯은 첫 주에 겪는 문제라 스냅샷을 미룰 수 없습니다. 여기까지가 매일 쓰는 부분이고, 여기가 재미없으면 나머지도 안 씁니다.
- **medium** — 두 번째 페이지(`alerts`), 좌우 요약 게이지, 핀 키, 선언 로더와 jq 매핑, 액션 레지스트리. 페이지가 둘이 되어야 페이징 코드에 의미가 생깁니다.
- **low** — 라우팅 선언화, 스필오버, 모듈 등록, 액자 트랜스포트, `returnToFirstAfter`.

처음부터 라우팅을 선언으로 만들지 않는 게 요점입니다. 규칙이 두 개일 때 규칙 엔진은 그냥 우회로이고, 세 번째 소스를 붙일 때 어떤 `match` 축이 실제로 필요한지가 비로소 보입니다.

**코어는 무엇이 꽂혔는지 모릅니다.** 소스를 늘리는 일이 파일 하나 추가하는 일이면 성공이고, 코어를 열어야 하면 실패입니다.
