# 페이지 편집기와 시뮬레이터

실기기 없이 페이지 구성·입력·문맥 전환을 검증하고 동일한 화면에서 설정을 편집한다. 실행 명령은 `bun run editor`, 기본 주소는 `http://127.0.0.1:31416`이다.

## 재사용과 격리

브라우저 연결마다 메모리에 시뮬레이터를 만든다. `PageBoard`, `DisplayLifecycle`, `HidDisplay`와 실제 키 렌더러를 재사용하며, HID 하드웨어 대신 키별 RGB를 브라우저로 보내는 가짜 장치를 연결한다. 실제 USB 장치, 활성 앱 감시기, 신호 DB는 열지 않는다. 샘플 신호와 가상 앱·잠금 상태만 사용한다.

각 키의 72×72 RGB 전송을 캔버스에 표시한다. 페이지 전환 CSS 애니메이션을 따로 만들지 않는다. 키별 지연을 주어 느린 전송·전환 취소·입력 차단을 확인한다. 실제 장치의 전송 속도와 밝기, OS 알림 타이밍을 대체하는 검증은 아니다.

## 편집과 저장

페이지 목록, 덱 프리뷰, 선택 항목 편집 영역을 한 화면에 배치한다. 페이지 조건·복수 소스/중요도/신선도 필터·소스별 키 영역·버튼 배치·전환 효과를 편집하며 미리보기에는 즉시 적용한다. 일반 배치와 영역 키 수를 분리해 표시하고, 현재 필터에 해당하는 신호 수도 실제 시뮬레이터 상태에서 계산한다. 버튼 이동은 배치 편집 모드에서만 가능하고, 시뮬레이션 모드의 클릭은 실제 down/up 입력 흐름을 따른다.

신호 편집기는 샘플 개수 조절과 별도로 id·label·중요도를 가진 신호의 추가/갱신, 삭제, 소스 전체 stale 전환을 실제 HTTP/저장 경로로 보낸다. 같은 소스의 같은 id는 갱신되고, 다른 소스의 같은 id는 별도 신호다.

설정은 명시적인 저장에만 반영한다. 서버는 공통 설정 검증과 원자적 갱신을 사용하고 인증 토큰·추가 설정·장치 활성화 여부를 보존한다. 읽은 뒤 다른 곳에서 설정이 바뀌면 버전 충돌로 저장을 거부하고 사용자의 초안을 유지한다. 실제 호스트에는 재시작 후 반영된다.

## 로컬 접근

편집기는 loopback에만 바인딩한다. Host와 Origin 검증, 프로세스별 임시 접근 토큰, CORS 비허용과 CSP로 다른 웹사이트의 설정 변경·WebSocket 접속을 차단한다. 기존 신호 HTTP 서버의 인증과 Origin 차단은 변경하지 않는다. 브라우저에는 소스 이름과 페이지 정의만 전달하고 관리자·소스 토큰은 전달하지 않는다.

## 검증

설정 보존·충돌·출처 검증, 시뮬레이터의 문맥 선택·수동 고정·잠금·키 입력·느린 전송·종료, 복수 필터·영역 배치·신호 수명 조작을 자동 검증한다. 브라우저에서 실제 캔버스 출력, 페이지와 버튼·필터·영역 편집, 저장과 충돌 안내, 좁은 화면 배치를 확인한다.
