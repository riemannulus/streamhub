# Streamhub Studio 캔버스 중심 UX 개편 설계

- 작성일: 2026-09-10
- 상태: 사용자 검토 대기
- 범위: Studio 편집 경험, 시각 자산, 실제 장치 적용, 대기화면

## 결정 요약

Studio를 시뮬레이터 중심의 다중 폼 화면에서 **캔버스 중심 장치 편집기**로 바꾼다.

1. 새 페이지는 샘플 신호가 없는 정적 빈 페이지로 시작한다.
2. 가운데 5×3 장치 캔버스, 왼쪽 추가 항목, 오른쪽 선택 항목 설정만 기본 화면에 둔다.
3. 신호 생성과 작업 환경 시뮬레이션은 닫혀 있는 `테스트` 서랍으로 옮긴다.
4. 키 이미지, 페이지 배경, 대기 이미지는 하나의 로컬 자산 저장소를 사용한다.
5. 편집 내용은 복구용 초안으로 자동 저장하고, `장치에 적용`이 영구 설정 저장과 실행 중 호스트 갱신을 함께 수행한다.
6. 첫 구현은 한 대의 15키·72×72 Stream Deck과 정적 PNG/JPEG/WebP만 지원한다.

## 문제

현재 Studio는 서로 다른 네 가지 작업을 한 화면에 동시에 노출한다.

- 페이지와 키 구성
- 자동 전환과 신호 필터 구성
- 샘플 신호 및 환경 시뮬레이션
- 저장과 초안 검증

이 때문에 사용자는 빈 키 하나를 설정하기 위해 페이지 ID, 규칙 우선순위, 신선도, 소스 영역 같은 내부 개념을 먼저 이해해야 한다. 브라우저가 편집 중인 `board`를 직접 소유하고 서버는 저장 시점에만 받기 때문에 복구 상태와 실제 적용 상태도 분리되어 있다. 저장된 보드가 없어도 Studio가 예시 보드를 만들고 `저장됨`으로 표시하므로, 미리보기와 실제 장치가 다를 수 있다.

시각 구성도 제한된다. 고정 키는 여섯 개 내장 아이콘과 단색만 지원하고 페이지 전체 배경은 없다. 비활성 세션과 정상 종료에서는 장치 펌웨어 로고만 복원하므로 사용자가 대기화면을 정할 수도 없다.

## 목표

- 처음 쓰는 사용자가 문서 없이 2분 안에 정적 페이지와 세 개의 키를 만들고 실제 장치에 적용한다.
- 기본 작업에서는 신호, 필터, 영역, 우선순위를 보지 않는다.
- Studio 캔버스와 실제 장치가 같은 렌더러와 자산을 사용한다.
- 편집 중 브라우저나 Studio가 종료되어도 최근 초안을 복구한다.
- 키 이미지, 페이지 배경, 정적 대기화면을 로컬 파일로 설정한다.
- 적용 상태와 실패 후 복구 방법을 한 문장으로 설명한다.
- 기존 설정은 마이그레이션 없이 계속 읽고 동일하게 렌더링한다.

## 비목표

첫 구현에는 다음을 포함하지 않는다.

- 여러 장치와 장치별 프로필
- 플러그인 또는 아이콘 마켓플레이스
- GIF 및 동영상 배경
- 자유로운 폰트 설치와 픽셀 단위 텍스트 편집
- 신호가 전달한 임의 액션 실행
- 원격 브라우저에서 Studio 사용
- USB 분리나 프로세스 강제 종료 뒤 커스텀 대기화면 보장

## 사용자 언어

제품 인터페이스는 구현 용어 대신 사용자의 결과를 말한다.

| 기존 표현 | 새 표현 | 노출 위치 |
|---|---|---|
| 신호 | 상태 | 고급 편집, 테스트 |
| 소스 | 데이터 연결 | 고급 편집 |
| 신선도 | 업데이트 상태 | 고급 편집 |
| stale / 미확인 | 업데이트 끊김 | 상태 필터와 테스트 |
| 소스별 영역 | 상태 자동 배치 | 추가 항목과 선택 설정 |
| 규칙 우선순위 | 자동 전환 순서 | 페이지 자동 전환 설정 |
| 초안 검증 | 문제 확인 | 상단 상태 메뉴 |
| 설정 저장 | 장치에 적용 | 상단 기본 동작 |
| 수동 고정 | 현재 페이지 유지 | 테스트 상태 설명 |

`페이지 ID`, Bundle ID, 모니터 ID와 정규화된 상태 ID는 `고급 설정`을 열었을 때만 보여 준다. 페이지 ID는 이름에서 자동 생성하고 충돌할 때 숫자를 붙인다.

## 정보 구조

```text
┌ 장치 이름  ● 연결됨 ─ 변경 상태 ─ 실행 취소/다시 실행 ─ [장치에 적용] ┐
├──────────────┬─────────────────────────┬──────────────────┤
│ 추가할 항목   │ 페이지 이름   [배경 설정] │ 선택한 항목 설정  │
│              │                         │                  │
│ 버튼          │       Stream Deck      │ 이름             │
│ 상태 자동 배치 │          5 × 3          │ 아이콘/이미지      │
│ 페이지 이동   │          캔버스          │ 누르면 할 일       │
│ 표시용 글자   │                         │                  │
│              │  〈  페이지 1  페이지 2  ＋ 〉│ [고급 설정]      │
├──────────────┴─────────────────────────┴──────────────────┤
│ ▸ 테스트: 샘플 상태 · 앱 전환 · 잠금 · 느린 장치 · 실행 결과          │
└───────────────────────────────────────────────────────────┘
```

### 상단 막대

- 장치 이름과 연결 상태
- `장치와 동기화됨`, `적용하지 않은 변경`, `저장됨 · 호스트 연결 안 됨`, `외부 변경 발견` 중 하나의 상태
- 실행 취소와 다시 실행
- 기본 동작인 `장치에 적용`
- `문제 확인`, JSON 가져오기·내보내기, 장치 설정은 더보기 메뉴

`다시 불러오기`는 기본 동작에서 제거한다. 외부 설정 충돌이 있을 때만 `외부 변경 불러오기`로 제시한다.

### 왼쪽 추가 항목

기본 목록은 네 가지로 제한한다.

- **버튼:** URL 열기, 앱 열기, 등록 명령 실행 중 하나
- **상태 자동 배치:** 선택한 키들에 연결된 상태를 자동 배치
- **페이지 이동:** 이전, 다음, 특정 페이지, 자동 전환 복귀
- **표시용 글자:** 실행하지 않는 고정 타일

항목을 키로 끌어놓거나 항목을 클릭한 뒤 빈 키를 선택한다. 빈 키를 직접 클릭해도 같은 네 가지 선택지를 보여 준다. 등록 명령의 실행 파일과 인자 규칙은 Studio 밖의 신뢰 설정에 계속 둔다.

### 가운데 캔버스

- 실제 5×3 비율과 키 사이 간격을 유지한다.
- 캔버스가 화면에서 가장 큰 시각 요소다.
- 선택 키에는 하나의 명확한 외곽선만 사용한다.
- 페이지 배경은 키 사이의 물리 간격을 제외한 360×216 논리 화면에서 자른 결과를 보여 준다.
- 페이지 탭은 캔버스 아래에 두고 추가, 복제, 순서 변경을 제공한다.
- 페이지 이름과 `배경 설정`만 캔버스 위에 둔다.

샘플 보드는 자동으로 현재 구성처럼 보이지 않는다. 설정된 보드가 없으면 캔버스 위에 다음 선택지만 보여 준다.

- `빈 페이지로 시작`
- `상태 대시보드로 시작`
- `JSON 가져오기`

템플릿을 선택하기 전 상태는 `예시`나 `저장됨`이 아니다.

### 오른쪽 선택 설정

선택 대상에 필요한 설정만 렌더링한다.

- 빈 키: 추가할 항목 네 가지
- 버튼: 이름, 아이콘 또는 이미지, 실행 동작
- 표시용 글자: 이름, 아이콘 또는 이미지
- 상태 자동 배치: 포함할 키, 데이터 연결, 중요도, 업데이트 상태
- 페이지 배경: 이미지, 맞춤 방식, 위치, 어둡게
- 페이지 탭: 이름, 기본 페이지, 자동 전환

자동 전환을 켜면 앱, 창 제목, 화면 조건을 보여 준다. 숫자 우선순위 입력은 없애고 자동 전환이 설정된 페이지 목록을 드래그해 평가 순서를 정한다.

### 테스트 서랍

기본값은 닫힘이다. 열었을 때만 다음을 제공한다.

- 샘플 상태 추가·갱신·삭제
- 데이터 연결의 업데이트 끊김 재현
- 활성 앱, 창 제목, 모니터 변경
- 화면 잠금과 깨우기
- 느린 장치 전송
- 버튼 실행 성공·실패 재현
- 전체 검증 기록 생성

새 페이지에는 샘플 상태가 없다. `샘플 채우기`를 눌러야 테스트용 상태를 생성하며 실제 설정에는 저장하지 않는다.

## 핵심 작업 흐름

### 정적 페이지 만들기

1. `빈 페이지로 시작`을 선택한다.
2. 빈 키를 누르고 `버튼`을 선택한다.
3. 버튼 이름, 아이콘, 동작을 설정한다.
4. 필요한 키에 반복한다.
5. `장치에 적용`을 누른다.
6. 연결된 호스트가 같은 전체 프레임을 전송하고 Studio가 `장치와 동기화됨`을 표시한다.

### 상태를 일부 키에만 표시하기

1. `상태 자동 배치`를 추가한다.
2. 기본으로 현재 빈 키 세 개를 선택하고 사용자가 키를 더하거나 뺀다.
3. 데이터 연결과 중요도를 선택한다.
4. 테스트 서랍에서 샘플을 요청할 때만 캔버스에 동적 상태가 나타난다.

페이지 전체 자동 배치는 고급 설정으로 남긴다. 기존 `page.signals`는 이 모드로 편집한다. 기본 흐름은 기존 `regions`를 사용자 친화적인 상태 자동 배치로 사용한다.

### 아이콘과 배경 설정

1. 키 또는 페이지 배경을 선택한다.
2. 내장 아이콘을 고르거나 이미지를 끌어놓는다.
3. `맞춤` 또는 `채우기`와 초점 위치를 선택한다.
4. Studio가 실제 72×72 렌더링 결과를 표시한다.
5. 적용 시 같은 자산 ID와 렌더러가 실제 장치에 사용된다.

### 대기화면 설정

1. 더보기에서 `장치 설정`을 연다.
2. `대기 화면`에서 기본 로고, 단색, 이미지 중 하나를 선택한다.
3. 잠금 시 사용과 유휴 시간을 정한다.
4. `장치에서 5초 미리보기`로 확인한다.
5. 적용하면 다음 잠금, 유휴 또는 정상 종료부터 사용한다.

유휴 대기화면에서 첫 번째 키 입력은 화면만 깨우고 액션을 실행하지 않는다.

## 편집 상태와 적용 상태

브라우저가 설정의 원본을 소유하지 않는다. 서버 측 `StudioSession` 모듈이 정규화된 문서와 이력을 소유하며 브라우저는 명령을 보낸다.

```text
브라우저 명령
    ↓
StudioSession ──→ DraftStore
    │                 복구용 자동 저장
    ├──→ Simulator ──→ 공통 DeckVisualRenderer ──→ 캔버스
    │
    └── apply()
          ├──→ ConfigStore 원자적 저장
          └──→ HostControl ──→ PresentationController ──→ 실제 장치
```

`StudioSession`의 외부 인터페이스는 세 가지 동작으로 제한한다.

```ts
snapshot(): StudioSnapshot
dispatch(command: StudioCommand): Promise<StudioSnapshot>
apply(expectedBaseVersion: string): Promise<ApplyResult>
```

모든 편집은 `dispatch`를 지나므로 페이지 참조, 키 중복, 자산 참조와 실행 취소 이력이 한곳에 머문다. UI는 전체 `board`를 임의로 바꾸지 않는다. 테스트는 같은 인터페이스에서 관찰되는 문서와 결과만 검증한다.

### 자동 초안

- 유효한 명령마다 300ms 디바운스로 `.streamhub/studio/draft.json`에 저장한다.
- 브라우저 연결이 끊겨도 서버 문서는 유지된다.
- Studio 재시작 시 초안이 적용된 설정보다 새로우면 `작업 이어서 하기`와 `적용된 설정으로 시작`을 제공한다.
- 폼 입력 중 유효하지 않은 문자열은 DOM 입력값에만 머물고 blur 또는 Enter에서 하나의 유효한 명령으로 확정한다.
- 페이지 ID 변경은 새 ID를 검증하고 모든 내부 참조를 한 명령에서 바꾼다.

### 장치에 적용

1. 현재 초안, 등록된 데이터 연결·명령, 모든 자산 참조를 검증한다.
2. 기존 설정 해시가 `expectedBaseVersion`과 다르면 저장하지 않는다.
3. 전체 설정 파일을 기존 원자적 저장 방식으로 갱신한다.
4. 실행 중 호스트의 인증된 로컬 제어 인터페이스에 프레젠테이션을 적용한다.
5. 호스트는 기존 입력을 취소하고 새 `PageBoard` 및 대기 설정을 만든 뒤 전체 프레임을 전송한다.

디스크 저장 후 호스트 적용만 실패하면 저장을 되돌리지 않는다. Studio는 `저장됨 · 장치에 적용하지 못함`과 재시도 동작을 보여 준다. 다음 호스트 시작에서는 저장된 구성이 적용된다.

호스트가 실행되지 않았으면 `저장됨 · 호스트 연결 안 됨`을 표시한다. 사용자가 별도의 재시작 규칙을 외우게 하지 않는다.

## 설정 모델

기존 필드는 그대로 읽고 새 시각 필드는 선택적으로 추가한다.

```ts
type AssetId = string;

type ImageLayer = {
  assetId: AssetId;
  fit: 'contain' | 'cover';
  positionX: number; // 0..1
  positionY: number; // 0..1
  opacity?: number;  // 0..1
};

type KeyAppearance = {
  color?: string;
  icon?:
    | {kind: 'builtin'; name: BuiltinIcon}
    | {kind: 'asset'; image: ImageLayer};
  showLabel?: boolean;
};

type PageAppearance = {
  backgroundColor?: string;
  background?: ImageLayer;
  dim?: number; // 0..1
};

type StandbyConfig = {
  mode: 'logo' | 'color' | 'image';
  color?: string;
  image?: ImageLayer;
  onLock: boolean;
  idleAfterMs?: number;
};
```

`PageDefinition`에는 `appearance?: PageAppearance`, 고정 키에는 `appearance?: KeyAppearance`를 추가한다. `streamdeck`에는 `standby?: StandbyConfig`를 추가한다.

기존 `button.color`와 문자열 `button.icon`은 계속 허용하고 검증 시 새 내부 표현으로 정규화한다. 기존 파일을 자동 재작성하지 않는다. Studio에서 해당 키를 수정해 적용할 때만 새 표현을 저장한다.

## 시각 자산

`VisualAssetStore`는 파일 시스템과 이미지 디코더 복잡성을 숨기는 깊은 모듈이다.

```ts
import(bytes: Uint8Array, declaredType: string): Promise<AssetMetadata>
read(id: AssetId): Promise<Buffer>
```

- PNG, JPEG, 정적 WebP만 허용한다.
- 업로드 크기는 8MiB, 디코딩한 전체 픽셀은 1,600만 개로 제한한다.
- 이미지 디코더가 확인한 형식을 사용하고 확장자와 브라우저 MIME을 신뢰하지 않는다.
- 방향 정보를 반영하고 sRGB 정적 PNG로 정규화한다.
- 정규화된 바이트의 SHA-256을 자산 ID로 사용한다.
- `.streamhub/assets/<sha256>.png`에 `0600` 권한으로 원자적으로 저장한다.
- 임의 경로와 원격 URL은 설정에 저장할 수 없다.
- 참조가 사라진 자산도 자동 삭제하지 않는다. 데이터 손실 없는 정리는 별도 유지보수 기능으로 미룬다.

브라우저 업로드는 기존 Editor capability가 필요한 `POST /api/assets`를 사용한다. 응답에는 자산 ID, 너비, 높이만 포함하고 로컬 경로는 노출하지 않는다.

## 렌더링

현재 키별 SVG 생성 로직을 `DeckVisualRenderer` 뒤로 깊게 만든다.

```ts
render(frame: DeckPage, presentation: Presentation): Promise<RenderedDeckFrame>
renderStandby(config: StandbyConfig): Promise<RenderedDeckFrame>
```

`RenderedDeckFrame`은 15개의 72×72 RGB 버퍼와 캐시 ID를 가진다. 브라우저 시뮬레이터와 HID adapter가 이 결과를 그대로 사용한다.

페이지 배경은 360×216 논리 화면에 맞춘 뒤 다섯 열, 세 행으로 자른다. CSS의 장치 간격은 시각적 물리 간격일 뿐 이미지 좌표에는 들어가지 않는다. 각 키는 다음 순서로 합성한다.

1. 페이지 배경 조각 또는 배경색
2. 키별 색상 오버레이
3. 사용자 이미지 또는 내장 아이콘
4. 레이블과 상태 정보
5. 비활성·실행 중·실패 피드백

빈 키도 페이지 배경 조각을 렌더링한다. 참조 자산이 없거나 손상되면 적용을 거부하고 현재 장치 프레임을 유지한다. 시뮬레이터는 같은 오류를 해당 키에 표시한다.

## 호스트 즉시 적용

호스트 HTTP 서버의 기존 관리자 인증 seam에 프레젠테이션 적용 동작을 추가한다. 브라우저에서는 호출할 수 없으며 Editor 서버가 설정 파일에서 읽은 관리자 토큰으로 loopback 요청을 보낸다.

```text
PUT /v1/presentation
Authorization: Bearer <admin token>
Origin 헤더 없음
Body: {expectedVersion, streamdeck}
```

호스트의 `PresentationController` 모듈은 다음 인터페이스를 제공한다.

```ts
apply(streamdeck: StreamDeckConfig, expectedVersion: string): Promise<PresentationStatus>
status(): PresentationStatus
```

`apply`는 데이터 연결, collector, action registry와 HTTP 서버를 재시작하지 않는다. 장치 보드, 시각 자산, 대기 설정만 교체한다. 적용 중 눌린 키와 실행 대기 액션은 취소하며 모든 물리 키가 놓인 뒤 입력을 다시 허용한다.

프로덕션은 인증된 loopback HTTP adapter, 테스트는 in-memory adapter를 사용한다. 별도 Unix socket이나 파일 감시는 만들지 않는다.

## 대기화면과 장치 수명주기

대기화면은 일반 페이지가 아니라 장치 상태다. 기존 `DisplayLifecycle`에 프레임을 선택적으로 받는 대기 동작을 추가한다.

- **화면 잠금·비활성 세션:** 입력을 취소하고 대기 프레임을 모두 전송한 뒤 HID를 닫는다.
- **호스트 정상 종료:** 제한 시간 안에서 대기 프레임을 전송하고 HID를 닫는다.
- **유휴 시간 경과:** HID를 유지한 채 대기 프레임을 표시한다. 첫 키 입력은 깨우기만 수행한다.
- **깨우기:** 최신 상태와 현재 페이지로 전체 프레임을 다시 전송한 뒤 입력을 허용한다.
- **USB 오류·프로세스 강제 종료:** 커스텀 화면을 보장하지 않는다. 장치 펌웨어 동작을 따른다.

대기 프레임 전송이 timeout되면 기존 실패 격리 규칙대로 핸들을 닫고 오류 상태를 표시한다. 실패한 핸들을 다시 사용하지 않는다.

## 오류와 복구

| 상황 | 사용자에게 보이는 결과 | 보존되는 상태 |
|---|---|---|
| Studio 브라우저 종료 | 다음 실행에서 `작업 이어서 하기` | 자동 초안, 자산 |
| 설정 외부 변경 | `외부 변경 발견`과 다시 불러오기 | 현재 초안 |
| 잘못된 이미지 | 파일별 이유와 다시 선택 | 현재 초안과 기존 자산 |
| 참조 자산 없음 | 적용 차단, 해당 키 강조 | 실제 설정과 장치 화면 |
| 호스트 미실행 | `저장됨 · 호스트 연결 안 됨` | 설정 파일과 초안 |
| 저장 성공, 장치 적용 실패 | `저장됨 · 장치에 적용하지 못함` | 새 설정, 이전 장치 화면 |
| 장치 전송 실패 | `장치 연결 오류`와 재시도 | 새 설정, 실패 격리된 핸들 |
| 대기화면 전송 실패 | 기본 로고도 보장하지 않음 명시 | 설정과 다음 재시도 |

오류 메시지는 내부 예외 문자열 대신 무엇이 보존되었고 다음에 무엇을 누를지 설명한다.

## 시각 방향

Studio는 스트리밍 대시보드가 아니라 물리 장치를 조립하는 작업대처럼 보여야 한다.

- 기본 바탕 `#E9EDF2`, 편집 표면 `#FFFFFF`, 장치 `#171B22`
- 선택 `#3973E6`, 정상 연결 `#2E8B70`, 주의 `#B87512`, 오류 `#C5483D`
- Pretendard 또는 시스템 한글 sans 하나만 사용하고 제목 20px, 섹션 14px, 본문 13px의 작은 위계를 유지한다.
- 둥근 카드의 반복 대신 캔버스, 설정 패널, 서랍이라는 실제 구조만 선으로 구분한다.
- 기억에 남는 요소는 실제 장치와 동일한 5×3 캔버스 하나로 제한한다.
- 장식 애니메이션은 사용하지 않고 적용 완료, 패널 열기, 드래그 결과에만 짧은 피드백을 준다.

키보드만으로 추가 항목 선택, 키 이동, 속성 편집과 적용이 가능해야 한다. 선택은 색만으로 표현하지 않고 외곽선과 텍스트를 함께 사용한다. `prefers-reduced-motion`에서는 전환을 제거한다.

## 구현 경계

기능은 다음 모듈에 집중한다.

| 모듈 | 책임 | 의존성 |
|---|---|---|
| `StudioSession` | 문서 명령, 이력, 자동 초안, 적용 상태 | DraftStore, HostControl |
| `VisualAssetStore` | 이미지 검증, 정규화, 원자 저장, 조회 | 파일 시스템, sharp |
| `DeckVisualRenderer` | 배경·키·아이콘·상태를 15개 RGB로 합성 | VisualAssetStore |
| `PresentationController` | 실행 중 보드와 대기 설정 교체 | PageBoard, DisplayLifecycle |
| Browser UI | 현재 snapshot 표시와 사용자 명령 전달 | StudioSession의 웹 adapter |

브라우저 UI, 실제 HID와 테스트가 자산 경로, 설정 해시, 렌더 캐시를 직접 다루지 않는다. 복잡성은 위 네 모듈 뒤에 머물러야 한다.

## 전달 단계

각 단계는 실제 사용 흐름을 끝까지 완성하는 수직 범위다.

### 1. 정적 페이지를 즉시 적용

- 캔버스 중심 shell과 선택 항목 inspector
- 빈 정적 페이지 시작
- 서버 소유 StudioSession과 자동 초안
- `장치에 적용`과 실행 중 호스트 갱신
- 기본 용어 교체

완료 기준: 표시용 글자와 기존 내장 아이콘 세 개를 배치해 재시작 없이 실제 장치에서 확인한다.

### 2. 사용자 이미지와 페이지 배경

- VisualAssetStore와 업로드
- 키 이미지 및 내장 아이콘 선택기
- 페이지 배경 자르기와 공통 렌더러
- 누락·손상 자산 오류

완료 기준: 한 이미지를 페이지 배경으로 적용하고 투명 아이콘이 있는 키를 Studio와 실제 장치에서 동일하게 확인한다.

### 3. 대기화면

- 장치 설정
- 정적 대기 이미지와 단색
- 잠금, 유휴, 정상 종료 수명주기
- 장치 5초 미리보기

완료 기준: 잠금에서 대기 이미지가 나타나고, 해제 후 최신 페이지가 복원되며, 유휴 상태의 첫 키는 액션을 실행하지 않는다.

### 4. 상태와 테스트의 점진적 노출

- 상태 자동 배치 추가 항목
- 자동 전환 순서 편집
- 테스트 서랍으로 기존 시뮬레이션 이동
- 페이지 전체 자동 배치를 고급 설정으로 유지

완료 기준: 정적 페이지만 만드는 사용자는 신호 필터나 샘플 데이터를 한 번도 보지 않고 작업을 끝낸다.

## 검증 전략

### 모듈 인터페이스 테스트

- StudioSession 명령이 유효한 문서와 실행 취소 이력을 유지한다.
- 자동 초안 복구와 외부 설정 충돌이 사용자의 초안을 덮어쓰지 않는다.
- VisualAssetStore가 형식, 크기, 픽셀 상한, 손상 입력과 경로 조작을 거부한다.
- DeckVisualRenderer가 같은 입력과 자산에서 동일한 RGB를 생성한다.
- PresentationController가 눌린 키와 실행 대기 액션을 취소하고 최신 프레임만 적용한다.

### 시각 회귀 테스트

- 빈 페이지, 사용자 키 이미지, 페이지 배경, 상태 타일, 대기화면의 15키 PNG golden을 둔다.
- 브라우저 캔버스와 headless HID adapter의 최종 RGB 해시가 일치해야 한다.
- 페이지 배경의 모서리와 행·열 경계를 검사해 자르기 순서를 고정한다.

### 브라우저 작업 흐름

- 최초 화면에 샘플 상태와 고급 용어가 없다.
- 빈 키에 버튼을 추가하고 이미지를 선택한 뒤 적용할 수 있다.
- 선택 대상이 바뀌면 관련 inspector만 보인다.
- 미적용, 적용 중, 동기화, 오프라인과 충돌 상태를 구분한다.
- 키보드 탐색, focus 표시, 좁은 화면과 reduced motion을 확인한다.

### 실제 장치 검증

- 정적 페이지 즉시 적용
- 15키 페이지 배경 방향과 색
- 사용자 아이콘 투명도와 글자 가독성
- 잠금·해제, 유휴 깨우기, 정상 종료 대기화면
- 적용 중 키를 누른 경우 stale 액션이 실행되지 않음

## 수용 기준

- 보드가 없을 때 `저장됨`이나 실제 구성처럼 보이는 샘플 페이지를 표시하지 않는다.
- 정적 페이지에는 사용자가 추가하지 않은 동적 상태가 나타나지 않는다.
- 세 개 키를 구성하고 실제 장치에 적용하는 기본 흐름에서 고급 설정을 열 필요가 없다.
- 키 이미지와 페이지 배경은 Studio와 실제 장치에서 같은 픽셀 방향과 자르기를 사용한다.
- `장치에 적용` 후 실행 중 호스트가 2초 안에 새 전체 프레임을 표시한다.
- 브라우저 종료 뒤 마지막 유효 초안을 복구할 수 있다.
- 커스텀 대기화면은 잠금, 유휴, 정상 종료에서 검증된 동작을 한다.
- 기존 구성과 신호 제공 액션 차단 정책은 그대로 유지된다.

## 결정된 제약

- 첫 대상 장치는 현재 지원 중인 15키·72×72 모델 한 대다.
- 첫 자산 형식은 정적 PNG/JPEG/WebP다.
- 페이지 배경의 논리 좌표는 360×216이며 키 사이의 물리 간격은 포함하지 않는다.
- 자동 초안은 서버 측 로컬 파일에 저장한다.
- 실제 적용은 기존 관리자 토큰을 사용하는 loopback HTTP adapter를 사용한다.
- 저장 성공 후 장치 적용 실패는 부분 성공으로 보고 저장을 되돌리지 않는다.
- 유휴 상태의 첫 키는 깨우기 전용이다.
- 기존 내장 아이콘과 색상 설정은 하위 호환한다.
